# Checkpoint 2: end to end (pipeline + Terraform + Kubernetes)

**Week 9 (Days 57–63).** About 4–5 hours in total.

## The brief
Nobody deploys by hand anymore. Every push to `main` should **test, build and deploy** the Notes app automatically, onto a platform that **Terraform** creates. You'll build that pipeline, entirely on free GitHub Actions minutes.

```
git push ─► test (pytest) ─► build + push image (ghcr.io, tagged with the commit SHA)
                                  │
                                  ▼
          kind cluster inside the runner ─► terraform apply (namespace, quota, secret, Redis)
                                  │
                                  ▼
                kubectl apply the app with that exact image ─► rollout status ─► smoke test
```

## Must have (acceptance criteria)
1. **Repo layout:** `apps/notes-app/` (copy it from this repo), `infra/` (Terraform), `deploy/` (the app's Kubernetes YAML), and `.github/workflows/`.
2. **Terraform** (`kubernetes` provider) creates:
   - the namespace, with an `owner` label
   - a **ResourceQuota**
   - a **Redis password generated by Terraform** (`random_password`), stored in a Secret. No human ever types it.
   - Redis (Deployment plus Service)
3. Running `terraform plan` right after `apply` shows **no changes**. Explain why that matters (hint: idempotency).
4. The **pipeline** runs tests on every push and pull request. It builds and deploys **only on `main`**.
5. The image is tagged with the **commit SHA**, never `:latest`.
6. Least privilege: `permissions: contents: read` at the top, with more granted only to the job that needs it.
7. The deploy waits for `kubectl rollout status`, then a **smoke test** proves the app works: add a note, read it back, and check `/readyz` reports `redis`. A broken app must turn the pipeline **red**.
8. A pull request with a failing test **cannot** deploy.

**Useful actions:** `actions/checkout`, `actions/setup-python`, `docker/login-action`, `docker/build-push-action`, `helm/kind-action`, `hashicorp/setup-terraform`.

**Two gotchas, so you don't lose an evening:**
- Images you push to ghcr.io start **private**. The deploy job needs its own `docker/login-action` step and `packages: read`.
- A Service named `redis` makes Kubernetes inject `REDIS_PORT=tcp://…` into your pods. Set `enableServiceLinks: false` in the pod spec if your app trips over it.

## Optional cloud extension (Azure)
Swap the kind step for AKS. Authenticate the pipeline with **OIDC (federated credentials), not a stored secret**. Keep Terraform state in an Azure Storage backend. Destroy everything afterwards.
